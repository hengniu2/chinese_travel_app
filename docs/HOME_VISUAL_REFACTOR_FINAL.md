# 首页 · 中国卡通插画风彻底重构 · 视觉分析与策略

## 第一阶段：视觉文化切换分析（不写代码）

### 1️⃣ 当前页面为什么偏欧洲风

| 维度 | 表现 | 原因 |
|------|------|------|
| **颜色** | 主绿+浅灰白底、区块同色或弱渐变 | 克制的 Material 色板、缺少高饱和红橙/绿/黄/蓝分区，节日感弱 |
| **字体** | 常规无衬线、字重 400/600、无手写感 | 未做「主标题明显大于副标题」的层级与字间距，偏理性 |
| **圆角** | 卡片 12、曾有大块 32 圆角 Section | 整体偏规整，中国商业风更偏 12–14 卡片、Section 少用大圆角 |
| **间距** | Section 上下 10–24、卡片 8–16 | 留白偏多，信息密度不足，呼吸感强 |
| **Icon** | Material 线型/圆角图标 | 非卡通风「彩色块+粗轮廓」，缺少饱满感 |
| **卡片结构** | 上图下文或横滑统一形态 | 缺少「贴纸人物卡 / 标签覆盖图 / 左图右文」等混排，节奏单一 |
| **模块** | 白底或弱色块、分割线细 | 未形成「推荐绿 / 亲子黄 / 周边蓝」的强分区色块 |
| **主视觉** | Header 图+渐变、标题偏小 | 缺少「卡通插画主视觉 + 大号手写感标题」的节日/亲子气质 |
| **底部导航** | 已改圆润+绿/灰 | 仍可强化为 22–24、label 略粗，更卡通风 |

### 2️⃣ 示例截图的视觉 DNA

- **高饱和渐变**：Header 红→橙，周边区蓝渐变；区块色明确。
- **卡通插画主视觉**：右侧人物/春节/亲子插画，左侧留出标题区；背景有纹样或简化元素。
- **手写感标题**：主标题大、加粗、字间距略紧，副标题弱化；不居中、偏左。
- **紧凑布局**：Section padding 12、卡片间距 8–10、Grid 行距小，密度高。
- **多种卡片排版混用**：上图下文（标准卡）、贴纸人物卡（阴影/偏移）、标签覆盖图（全图+左上胶囊+底部渐变遮罩+白字）、左图右文（紧凑）。
- **模块独立背景色**：推荐浅绿、亲子浅黄、周边蓝渐变；不用全白。
- **强标签系统**：热门红胶囊、有趣的一天绿胶囊、城市灰块、角标 2~8 人/中信。
- **图片主导内容**：Header 插画、活动卡真实摄影图铺满，无灰占位。

## 第二阶段～第十一阶段：重构策略说明

### 二、顶部 Header
- 高度 **30–35%**（取 32%）。
- **卡通主视觉**：右侧插画风 URL（或本地 asset），背景高饱和红橙渐变。
- **主标题**：左侧大号「爱你老己的新春首站之旅」类文案，加粗、字间距略紧；副标题小、弱化、不居中。
- **搜索栏**：顶置、白色胶囊、圆角 30+、定位 icon、高 44–48。

### 三、功能入口
- **两排**：每排 5 或 6 个（保留 12 个入口），不三排。
- Icon 卡通风（彩色背景块）、标签黑色偏重、间距压缩约 30%。

### 四、模块背景分区
- 推荐区 **浅绿**、亲子区 **浅黄**、周边区 **蓝色渐变**；Section **不用大圆角**，色块分区。

### 五、混合卡片排版
- **类型 A（上图下文）**：亲子区小卡，图 16:9 或固定高，下为标题+城市标签。
- **类型 B（贴纸人物卡）**：推荐区，图带阴影、略偏移，人物卡感。
- **类型 C（标签覆盖图）**：周边活动，图全铺、左上「热门」红胶囊、底部渐变遮罩、白字标题+日期城市。
- **类型 D（左图右文）**：亲子区可混用一列左图右文紧凑卡。
- 每模块至少两种卡片形态，避免整齐网格感。

### 六、圆角
- Section 无大圆角；卡片 **12–14**；小标签胶囊；搜索 **30+**。

### 七、间距
- Section padding **12**；卡片间距 **8–10**；Grid 上下减约 30%。

### 八、Overflow 修复
- 所有 Row 内长文案用 **Flexible/Expanded**；文本 **maxLines + ellipsis**；横滑列表用**固定高度**，卡片内用 **Flexible + LayoutBuilder** 或固定高度约束，保证 0 overflow。

### 九、底部导航
- 圆润卡通风图标、**22–24**、选中绿、未选灰、label 略粗。

### 十、图片
- Header **插画风**；内容区 **旅行摄影**；图铺满卡片、无灰占位。

### 十一、视觉节奏
- 卡片大小不一（大卡/小卡）、有的有渐变、有的有标签覆盖、有的纯图有的图文混排，页面更生动。

## Overflow 修复说明（第九阶段落地）

1. **周边活动横滑**：ListView 固定高度（如 200.h），卡片 `SizedBox(height: 200.h)`，内层 Column 使用 `Flexible` 包住图片区，底部 Padding 固定，保证总高 ≤ 200.h。
2. **所有 Row 标题行**：模块标题、芯片、「更多」等用 **Expanded/Flexible** 包文字，**maxLines: 1**、**overflow: TextOverflow.ellipsis**。
3. **人物卡/亲子卡**：姓名、标题、日期城市等全部 **Expanded + maxLines + ellipsis**。
4. **不写死会撑破的高度**：横滑卡片高度由外层 SizedBox 约束，内层用 Flexible 分配，避免 Column 子项之和超过约束。

完成以上后，保证 **0 RenderFlex overflow**。

## 5️⃣ 本次实现中的 Overflow 修复说明

1. **周边活动卡片（类型 C）**  
   使用 **固定高度** `SizedBox(width, height: 200.h)`，内容为 **Stack(fit: StackFit.expand)**：全图铺满 + 左上角「热门」+ 底部渐变遮罩。无 Column 纵向弹性，故不会溢出。

2. **亲子活动卡片（类型 A）**  
   使用 **固定尺寸** `SizedBox(width: 112.w, height: 124.h)`，内层 Column 为：固定高度图片区（68.h）+ **Expanded** 包住标题区，总高严格等于 124.h，不会溢出。

3. **推荐区人物卡（类型 B）**  
   无外层固定高度约束，但内容为：Padding + 固定高图（88.h）+ Padding + Row(Icon + Expanded(Text))，总高度由内容自然撑开，且 Row 内文案已用 Expanded + maxLines + ellipsis，不会横向溢出。

4. **所有 Section 标题行**  
   「周边活动」「享梦游种草官」「亲子活动」等 Row 中，标题或芯片用 **Expanded**，右侧「更多>」「查看全部>」用 **Flexible**，所有 Text 均 **maxLines: 1**、**overflow: TextOverflow.ellipsis**，避免小屏横向溢出。

5. **横滑列表高度**  
   亲子区 ListView 高度 **124.h**，与 _CardTypeA 的 124.h 一致；周边区 ListView 高度 **200.h**，与 _CardTypeC 的 200.h 一致，卡片不会超出列表项高度。
